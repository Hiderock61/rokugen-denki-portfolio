# 六弦電気工房｜Webサイト改善ケーススタディ

架空の個人ギター修理店「六弦電気工房」を題材にした、Webサイト改善のポートフォリオです。意図的に問題を残した修正前版から、既存の表示と機能を守りながら3工程で改善した完成版までを比較できます。

## 公開ページ

- 完成版: `index.html`
- ケーススタディ: `case-study.html`
- 修正前版: `before/index.html`

GitHub Pagesの入口はルートの `index.html` です。各ページの移動には相対パスを使用しているため、リポジトリ名を変更しても動作します。

## フォルダ構成

```text
rokugen-denki-portfolio/
├── index.html          # 完成した店舗サイト
├── style.css           # 完成版専用CSS

├── case-study.html     # ケーススタディ最終版

│   └── script.js       # 修正前版の動作不良を含むJS
└── assets/
    └── README.md       # 素材の使用状況
```

## 修正前版で確認した問題

1. スマートフォン用メニューが正常に動作しない
2. 料金表がスマートフォンの画面幅からはみ出す
3. 問い合わせボタンが小さく目立たない
4. 営業時間がページ下部に埋もれている
5. 店舗説明が長く読みづらい
6. 修理メニューの違いを比較しにくい

修正前版は比較用の成果物です。上記6点は意図的に維持しており、完成版のCSSとJavaScriptは適用していません。

## 改善工程

### 1. 機能不良とスマートフォン表示の修正

- スマートフォン用メニューの開閉を実装
- `MENU` / `CLOSE` の表示切り替えを実装
- 項目選択後の自動閉鎖を実装
- PCの表形式を維持し、スマートフォンの料金表をカード形式へ変更

### 2. 問い合わせ導線と営業時間の改善

- 相談ボタンを押しやすいサイズと具体的な文言へ変更
- 修理メニュー後とページ末尾に相談導線を配置
- 営業時間を修理メニュー直後へ移動
- 営業日、土・日、定休日を分けて表示

### 3. 店舗説明と修理メニューの情報整理

- 店舗説明を短い導入文と3つの要点へ整理
- 修理メニューを「メニュー名／対応する症状／主な作業」に統一
- 料金表は価格確認、修理メニューは症状と作業の確認という役割に分離

## ケーススタディ

最終版は店舗サイトのブランド表現とは分離し、実務ポートフォリオとして情報を短時間で比較できる設計にしています。

- 白・薄いグレーを基調とし、茶系1色をアクセントに使用
- ゴシック系フォントへ統一
- 固定ヘッダーとページ内リンクの着地点を調整
- 6つの問題を小型カードで一覧化
- 3工程を同じ情報構造で表示
- スマートフォンの修正前後比較をカード形式で表示
- 導線ボタンの高さ、角丸、文字サイズを統一

## GitHub Pagesでの公開

リポジトリ直下へこのフォルダの中身を配置し、GitHub Pagesの公開元をリポジトリのルートに設定します。公開後のURL例は次のとおりです。

```text
https://<ユーザー名>.github.io/<リポジトリ名>/
https://<ユーザー名>.github.io/<リポジトリ名>/case-study.html
https://<ユーザー名>.github.io/<リポジトリ名>/before/
```

問い合わせ先の `info@example.com` と住所は架空です。
